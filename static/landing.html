// How it works

Three steps. Same as the incumbents.

If you've integrated reCAPTCHA before, you've done this exact dance.

STEP 01

Embed the widget

One script tag and a div with your data-sitekey. The widget renders, fetches a puzzle, solves it in a worker.

<div data-sitekey="a1b2…"></div>
<script src=".../captcha-widget.js"></script>
STEP 02

Form submits with a token

The widget solves the puzzle in a worker and writes one opaque token into a hidden captcha-token input. Your form POSTs as usual — no JS rewrite needed.

// hidden input — opaque, forward verbatim
name="captcha-token"
7b226368616c6c656e67…
STEP 03

Verify server-to-server

Your backend forwards the token to POST /v1/verify with your site secret. You get success: true|false — time-on-page and behaviour are re-scored server-side.

# curl from your server
curl -X POST \
 -H "Authorization: Bearer $SECRET" \
 -d '{"token":"7b226368…"}' \
 api.bollwark.eu/v1/verify

// FAQ

Questions people actually ask.

How is this different from FriendlyCaptcha or Altcha?

Those are the right things to compare us to — not reCAPTCHA. Altcha is open source and self-hostable like us, but it's pure proof-of-work with no managed risk scoring or hosted dashboard; we add two-pass scoring, a hosted option, and an admin UI. FriendlyCaptcha is a polished, established privacy SaaS — but its server is closed and there's no self-host, so you're still renting a black box. Bollwark is the one that's open end to end and yours to run. They're more mature; we're more transparent and more portable — and because the code is MIT, you can verify every claim on this page yourself.

You're new — what if Bollwark shuts down?

That's exactly what the MIT license is for. The server and widget are open source, so a hosted service going away can't strand you: export your config, run the same binary on your own box, and keep going with the identical widget and API. You never bet your front door on our survival — which is more than the closed incumbents can offer, however established.

Why proof-of-work? Doesn't it drain mobile batteries?

The default difficulty (18 leading zero bits) takes a few hundred milliseconds on a modern computer and a few seconds on a low-end phone — and the solve starts as soon as the widget mounts, so it usually finishes before the visitor is done with the form. The widget runs in a Web Worker so it never freezes the page. Difficulty escalates only for requests that already look like bots; most humans never notice it ran.

Is it accessible?

There's no image-text or audio puzzle to solve — accessibility by design. The proof-of-work runs in the background; the most a visitor ever does is click an "I'm not a robot" checkbox. High-risk requests get a harder proof-of-work, never a visual challenge that screen-reader users can't complete.

How is this GDPR-compliant?

Bollwark is cookie-free — no client-side storage, no third-party loading, no cross-site identifiers — so there's nothing on the visitor's device to consent to. Signals run server-side under legitimate interest with data minimization: client IPs are truncated before they're written to the durable decision log, and the log is pruned on a 72-hour retention window by default. That posture lets most operators avoid the cookie-banner overhead that ad-tech CAPTCHAs trigger. (Enabling the optional IP-reputation or TLS-fingerprint signals is a heavier posture — consider a DPIA. As the data controller, the final call is yours.)

Can I migrate from reCAPTCHA / hCaptcha / FriendlyCaptcha?

Yes. The widget API is intentionally similar: one stylesheet, one script, one div with a site key, one server-side verify call. Like the incumbents, the token is an opaque string — you forward it verbatim to the verify endpoint, no parsing required — so the integration is a small adapter, not a rewrite.

What happens when I exceed my plan's verification quota?

We don't hard-block your traffic mid-month. You'll get notifications at 80% and 100%, and overage is billed at $1 per 10,000 extra verifications. If you regularly run over, the next tier is almost certainly cheaper.

What if I want the hosted version but with my own SLA / region / contract?

Enterprise plans cover dedicated regions (EU, US, AP), custom DPAs, on-prem deployment, and SLOs above 99.95%. Email us — these conversations usually take less than a week.

Why Rust?

Because a security primitive sitting in front of every signup form should be a single static binary with no runtime, predictable memory behavior, and deployment that doesn't depend on a package manager. Also: it's genuinely fast — most decisions resolve sub-millisecond.
